# Give it continuity and initiative

**Created:** 2026-09-07 · **Last-updated:** 2026-09-07 · **Status:** DRAFT

Tomorrow's conversation should retain Lucy's supplier preference without mistaking yesterday's stock snapshot for today's inventory. A reusable opening procedure should improve consistency without acquiring authority. A message arriving twice should create one request. A scheduled check should run while Lucy is away.

These are four different continuity problems. You implement durable context and provenance, local versioned skills, one Telegram adapter with authenticated intake, and persistent schedules and stock conditions. The adapter is a replaceable interface to the same owned loop. The scheduler creates bounded work rather than continuously consuming model tokens.

Chapter 7 introduces an actual supervised execution path. Unattended work still produces reports and drafts. Later deployment work makes that path maintainable; the next part first supplies the boundaries needed for consequential action.
