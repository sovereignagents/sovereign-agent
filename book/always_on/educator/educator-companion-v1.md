# Teach the always-on agent

**Created:** 2026-09-08 · **Last-updated:** 2026-09-08 · **Status:** DRAFT educator companion v1

Every chapter now has a classroom notebook and an instructor guide. Chapter 1 also has a second lesson on prompt wording, system messages and the Python harness. These companions support the construction chapters; they do not replace building the complete components explained in the manuscript.

## Choose the classroom environment

The two Chapter 1 notebooks run standalone on Python 3.11 or newer with no installation or credentials. Chapters 2–16 use the cumulative Python 3.14 book environment and a matching Sovereign Agent source checkout. Set `SOVEREIGN_AGENT_REPO` if the notebook is opened outside that checkout. Each later notebook checks its checkpoint hash before running the supplied cumulative experiment.

A notebook server is optional. From the repository root, the included standard-library runner executes saved cells and retains a new JSON evidence file:

```bash
uv run --python 3.14 python book/always_on/educator/run_lesson_v1.py --chapter 2 --output /tmp/lucy-ch02-class.json
```

Use a new output filename for a later retained run. Read and edit the notebook cells in your editor before executing them; the runner uses the saved file. For the second Chapter 1 lesson, choose `--chapter 1 --follow-on`. The runner adds no package dependency. The book conventions describe setup for the cumulative environment.

## Teach and assess the work

Allow ninety minutes for each chapter lab and sixty minutes for the Chapter 1 follow-on. Start with a written prediction. Students then implement one scoped decision function, test it against independent expected outcomes, inspect and execute the related cumulative checkpoint, and add a transfer case. The instructor guide supplies prerequisites, timings, expected observations, a worked answer, misconceptions, remediation and an evidence-based rubric.

Student work and supplied evidence are distinct. An untouched starter reports `NOT_SUBMITTED`; an empty transfer reports `TRANSFER_NOT_SUBMITTED`. Running the reference program or the worked answer does not pass the student's exercise. Collect the original function, its cases, a runtime data-flow trace and an exit ticket before awarding credit. A passing function is evidence about its stated contract, not the whole runtime.

The later notebooks use fixture models and channels. Some checkpoints start real local supplier or worker processes, and Chapter 11 starts a bounded local MCP process. Default runs do not send Telegram messages, make real purchases, call a model provider, run a container or install a host service. Chapter 15's restore experiment does not establish host uptime. Follow separately labelled chapter procedures for those observations.

These are draft teaching materials with execution checks. Teacher rehearsal, classroom outcomes, an external editorial judgment and publisher acceptance remain separate. The chapters continue to publish through Prof Rod's existing book; these downloadable artifacts create no additional book website.
